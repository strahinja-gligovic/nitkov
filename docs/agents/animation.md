# Animation: the move-set pipeline

How fighters are animated: moves as data in `data/moves/humanoid.tres`, generated by `tools/moveset/build_moveset.py`, played by `AnimDirector` with `TimeRemap` pinning key poses to simulation beats. Read this before adding or retiming a swing, cast or reaction, or when a pose lands at the wrong moment.

## Add or change a cast move

1. **Pick a clip.** A clip id is `<prefix>/<name>`, with the prefixes in `AnimLibrary.SOURCES` (`ual1`, `ual2`, `m2m_addon`). List a source's clip names with
   `uv run --no-project python -I -c "import json,struct,sys; b=open(sys.argv[1],'rb').read(); n=struct.unpack_from('<I',b,12)[0]; print(sorted(a['name'] for a in json.loads(b[20:20+n])['animations']))" assets/animations/UAL2_Standard.glb`.
   The clips are authored right-handed and the gauntlet is the left hand, so a one-handed throw usually wants `mirror=True`.
2. **Add the entry to `CAST_MOVES` in `tools/moveset/build_moveset.py`.** Never hand-edit `humanoid.tres`: the next regenerate overwrites it. A cast needs exactly six `keys` in clip seconds, ascending: start, antic, go, contact, settle, end (see *Key poses* below). Contact is the frame where the spell leaves the hand. A one-arm throw from the gauntlet takes `left_arm_only=True` (`cast_bolt`, `cast_dart`, `cast_point`); a move that needs the whole body leaves it off (see *Layers*). Set `strike`, `hold`, `settle_fraction`, `blend_in`, and a longer `blend_out` (0.15 to 0.25) if the move ends far from the guard.
3. **Regenerate:** `uv run --no-project python -I tools/moveset/build_moveset.py`. Done when it prints `moves: N` with your move counted, and the unit tests pass. `tests/test_move_set.gd` checks that the clip exists in its source, the keys ascend and stay inside the clip, and (once a spell points at the move, step 6) that it has six keys.
4. **Compare it with the current move in the real pipeline:**
   `godot_console --path . --fixed-fps 60 -- --gallery=-,cast_new --gallery_spell=ice_spike --gallery_angle=135 --hide_fx --hide_hud --cast_probe --shots=0.55,0.66,0.8 --quit=1`.
   `-` is the spell's own move. The gallery presses cast at 0.5 s, so the release is at 0.5 s plus the spell's windup. Repeat with `--gallery_walk=0,1` and `--gallery_leap=0.3` to see the layered version (see *Layers*). Every gallery option is listed at the top of `src/debug/anim_gallery.gd`. Done when the shot at the release shows the hand at full reach toward the target.
5. **Check the hand against the spawn point.** For a projectile spell, read the two lines `--cast_probe` prints (see *The hand and `cast_origin`*). Done when the `next frame` line is within about 0.2 m of `cast_origin` and the `releases` line is no further off than the current moves in the table there.
6. **Point the spell at it:** set `animation = &"cast_new"` in `data/spells/<id>.tres`. You don't need to change `windup` and `recovery`: the move retimes itself to them. Done when the unit tests pass.

To retime an existing swing, change `windup` / `active` / `recovery` in `data/weapons/longsword.tres`, then regenerate (step 3). The regenerate also re-bakes that swing's `lunge_profile`.

## Key poses and TimeRemap

The simulation decides when things happen and the clip has its own idea, so `TimeRemap` does not stretch the clip evenly. It pins each key to a simulation time and plays the clip linearly between neighbouring keys. As a result, holds stretch and the strike compresses.

For swings and casts, `TimeRemap.swing_keys(windup, active, recovery, strike, hold, settle_fraction)` builds the six simulation times that pair with the six clip keys:

| Key | Simulation time | Meaning |
|---|---|---|
| start | 0 | the pose when the action starts |
| antic | `max(go - hold, go * 0.5)` | the wind-up extreme, held `hold` seconds |
| go | `max(contact - strike, contact * 0.4)` | the strike begins |
| contact | `windup` | the blade reaches the target or the spell leaves the hand: the first active frame |
| settle | `contact + active + recovery * settle_fraction` | the follow-through stops |
| end | `windup + active + recovery` | the action ends |

- A cast passes `active = 0`, so its contact is exactly the simulation's release in `Fighter` (`action_time >= spell.windup`).
- A short windup squeezes `hold` first and then `strike`, so the 0.4 / 0.5 floors keep the beats in order. The go floor caps the effective `strike` at 0.6 × `windup`: a larger value changes nothing.
- Example: Ice Spike (windup 0.15, `strike` 0.065, `hold` 0.015) gives go 0.085 and antic 0.07. The regenerate prints each swing's simulation keys, e.g. `light_1 ... (sim keys 0.000, 0.100, 0.100, 0.150, 0.230, 0.530)`.
- **Hard invariant:** `build_moveset.py` has a Python copy, `swing_keys()` and `remap()`, which bakes the lunges. If you change `TimeRemap.swing_keys`, change the Python copy too and regenerate, or the baked footwork drifts off the drawn feet.
- If a swing or cast move doesn't have exactly six keys, `AnimDirector._swing_time` silently falls back to even timing, so contact no longer lands on the beat. The test catches this for every attack and spell.

All other moves use `TimeRemap.timed`: their keys land at the `sim_keys` fractions (0 to 1) of the action's duration, or are spaced like the clip when `sim_keys` is empty. With `sim_keys` set, the keys may go out and back (`block_impact` is `[0.0, 0.05, 0.0]`), and the test skips the ascending check for those moves.

## AnimMove fields that carry conventions

The field docs are in `src/animation/anim_move.gd`. These are the parts that aren't obvious from it:

- `mirror` and `chain_mirror` bake a `<clip>@mirror` copy (`AnimMirror`, which reflects in skeleton space and swaps `_l`/`_r` twins). `chain_clip` splices a second clip in at `chain_at`, and the keys then count on the joined timeline. `clip_from` trims the start, and the keys count from the cut. The baked library name is `AnimMove.baked_name()`.
- A `blend_in` at or below `SlotPair.SNAP` (0.03 s) snaps the pose in at full weight. The director's clock stops during hit-stop (`dt = 0`), so a reaction with a longer blend would not appear until hit-stop ends. Keep reaction `blend_in` at 0.03 or less.
- The incoming move crossfades over the longer of its own `blend_in` and the outgoing move's `blend_out`, unless it snaps.
- `recover` names a presentation-only move that plays when a swing ends with nothing following it.
- Root motion is cancelled (`tree.root_motion_track`): the simulation moves the body. A swing's step forward reaches the game only through `AttackData.lunge_profile`, which is baked from the clip's root curve.

## What the regenerate writes

- **`data/moves/humanoid.tres`**: every move in `LOCO_MOVES`, `MELEE_MOVES`, `CAST_MOVES`, `REACT` (`tools/moveset/moves_react.py`) and `AIR_MOVES`. Ids must be unique across those groups (an assert enforces it).
- **`lunge_profile` in `data/weapons/longsword.tres`**, for `light_1`, `light_2`, `light_3` and `heavy` only. Each profile is sampled at 60 Hz (`AttackData.LUNGE_STEP`) through the same remap, from the root curves in `tools/moveset/data/root_curves.json`, and scaled by `BODY_SCALE`.
  - The bake inserts the profile after the swing's `arc =` line. It also deletes any `lunge_scale` line in that block, so `AttackData.lunge_scale` stays at 1 for the four swings; the lunge follows the move's keys, `strike`, `hold` and the swing's timing (`BODY_SCALE` is the body-size ratio, shared by all four).
  - A new swing id needs a root curve labelled `<id> = ...` in `root_curves.json` and its id added to the tuple in `bake_lunges`. The measuring tools that produced the curves (from root-motion copies of the clips) are not in the repo.
- **Slash arcs.** For the four swings they come from `slash_fit.fits()`, which uses the measured tip positions in `tools/moveset/data/keys_final.json`. The arcs overwrite the `slash_*` values written in `MELEE_MOVES` for those four, so editing them has no effect; a swing missing from the list in `fits()` keeps its hand-written values. The fits don't follow a change to a swing's keys.

Run the regenerate after any change to a move in the Python, or to a swing's windup, active or recovery. Running it with nothing changed rewrites both files byte for byte, so a diff after a run is a real change. Clips are converted at load (`AnimLibrary`), so no `--import` is needed after a regenerate.

## Layers, and casts on the move

`AnimDirector` has three crossfading slot pairs: full body over locomotion, then the upper body, then the left arm.

- **Choosing the layer.** At the start of each cast (per `action_serial`), the cast goes to a layer if the fighter moves at `CAST_ON_THE_MOVE_SPEED` (1 m/s) or faster, is airborne, or the move is `left_arm_only`.
  - `left_arm_only` moves use `CharacterRig.left_arm_filter()` (`LEFT_ARM_BONES`: the spine from `spine_02`, neck, head and left arm, plus its fingers). The sword arm keeps its pose, so its blade can't swing into the head.
  - All other layered casts use `upper_body_filter()` (from `spine_02` up, both arms).
- **`LayerAim`** (in `anim_director.gd`) turns `spine_01` / `spine_02` so a layered cast's chest faces where it faces in its own clip. Without it, a level jab over a run's forward lean would punch the floor.
- **Whole-body casts lose their leg work on the move.** `cast_sweep`, `cast_wall`, `cast_nova`, `cast_call` and `cast_javelin` aren't `left_arm_only`, so on the move or in the air they play on the upper layer. LayerAim keeps their chest right, but the nova's fists stop around the waist.

## The hand and `cast_origin`

`Fighter.cast_origin()` is fixed relative to the body: 0.8 m forward, 0.15 m left, 1.3 m up. It is never read from animation, so the simulation stays deterministic. Projectile spells (`ProjectileSpell`: firebolt, ice_spike, lightning_bolt, wind_slash, wind_spear) spawn there. The animation's job is to bring the gauntlet hand to that spot on the contact key.

`FighterVisual._on_spell_cast` fires the `SpellFx.release` flash at the gauntlet orb as last drawn. That is the frame before contact, because the release happens in a physics tick before the frame draws. `--cast_probe` prints both:

- the `releases` line: what `SpellFx` got;
- the `next frame` line: the contact pose.

A fast strike moves the hand a long way in that one frame. Standing numbers from the gallery (`releases` / `next frame`):

- firebolt: 0.14 / 0.12 m
- lightning_bolt: 0.18 / 0.09 m
- wind_spear: 0.20 / 0.17 m
- wind_slash: 0.26 / 0.21 m
- ice_spike: 0.33 / 0.19 m

Ice Spike's dart throw whips from beside the head, so its flash shows behind the spike.

To close a gap:

- move the contact key to where the arm is already extended;
- or lengthen `strike` (up to 0.6 × `windup`), which shrinks the clip time covered by the last frame before contact.

Flame Wall, Frost Nova and Lightning Strike don't spawn at `cast_origin`, so their contact key is their beat instead (Wind Spear is a signature but a projectile, so it follows the rule above):

- `cast_wall`: the overhand peak;
- `cast_nova`: the fists at the floor (about 0.3 m up);
- `cast_call`: the fist raised to the sky (about 2 m up).

## Reactions

`AnimDirector._full_body` picks the reaction from the simulation state:

| State | Move |
|---|---|
| `FLINCH` | `flinch`, or `flinch_heavy` when `action_duration >= 0.35` |
| `STAGGER`, `stagger_kind == &"guard_break"` | `guard_break` |
| `STAGGER`, `&"shatter"` | `knockdown` (Hit_Knockback spliced into LayToIdle) |
| `STAGGER`, `&"shock"` (Lightning Strike) | `stagger_shock`, plus the `ShockJitter` modifier for the duration |
| `STAGGER`, any other kind (`&"parried"`, a spell's stagger) | `stagger`, or `stagger_long` when `action_duration >= LONG_STAGGER` (1.3 s) |
| airborne, not leaping, `knockback` above `BLOWN_SPEED` (4 m/s) | `blown`; a forward shove shows the `leap_air` tuck instead |
| `DEAD` | one of the moves whose id starts with `death`, picked per death |

Any move named `death*` joins the death pool automatically. `FighterVisual` plays the presentation-only overlays through `AnimDirector.play_overlay()`:

- `block_impact` and `parry` on the upper layer;
- `entrance`, `taunt`, `leap_land` and `blink` on the full body.

**To add a stagger kind:**

1. In the simulation, set `SpellHit.stagger_kind`, or pass the kind to `FighterState.apply_stagger`.
2. Add a branch in `AnimDirector._stagger_move`.
3. Add the move to `REACT` in `moves_react.py`.
4. Add its id to `REQUIRED` in `tests/test_move_set.gd`.

Most reactions place their keys with `sim_keys` fractions of the stagger (`knockdown` is spaced like its clip). The `twitch()` helper in `moves_react.py` builds `stagger_shock`'s jerking keys.

## Checking a move

- **Side by side:** the gallery command in step 4.
  - `--gallery_angle`: 0 is the sword side, 90 the front, 180 the gauntlet side.
  - `--gallery_turns=0,90`: several sides in one frame.
  - Reactions: `--gallery=stagger_shock,stagger --gallery_replace=stagger_shock --gallery_strike=0.3` lands a real Lightning Strike on the row at about 1.2 s.
- **In a duel:** add `--spectate=4 --spectate_angle=30 --spectate_on=player --hide_fx --hide_hud` to an autopilot run for a side camera that follows the player.
- **Numbers:**
  - `--cast_probe` checks the hand at release.
  - `--probe` writes `screenshots/probe.csv` every frame, for every fighter: action, `action_time`, sword tip, both feet (`ball_l` / `ball_r`), gauntlet hand, plus `HIT` rows. For a swing, the tip on the row where `action_time` reaches `windup` is the contact pose. The feet show skating against the body's position.
- **Tests:** `tests/test_move_set.gd` and `tests/test_time_remap.gd`. Run the unit-test command from `CLAUDE.md`.

For screenshot timing, open-ground spawns, slow motion and contact sheets, see `docs/agents/verification.md`.

## Gotcha: modifier poses exist only during the skeleton update

In Godot 4.7, a `SkeletonModifier3D`'s changes apply only inside the skeleton's update, and are restored right after it. That includes `StrideTwistModifier`, `LeanModifier`, `LookAtModifier3D`, `BreathModifier`, `HitReactModifier`, `LayerAim` and `ShockJitter`.

- Rendering, skins and `BoneAttachment3D` see the final pose.
- `get_bone_global_pose()` called from ordinary `_process` code returns the clip pose without the modifiers.
- The skeleton runs in `MODIFIER_CALLBACK_MODE_PROCESS_MANUAL`. `rig.skeleton.advance(delta)` in `FighterVisual._process` only schedules the pass, and modifiers run only when something dirtied the skeleton.

So, to read a final bone pose, connect to `skeleton_updated`:

- `FighterVisual._on_pose_final` does this for `drawn_tip` / `drawn_feet` and the blade trail. Read the sword through `CharacterRig.sword_transform()` from there.
- `LightningChargeFx`, `LightningShockFx` and `tests/test_procedural_layers.gd` do the same.

Modifiers apply in child order. `AnimDirector.build` adds `LayerAim` and `ShockJitter` before `FighterVisual._build_modifiers`, so the procedural lean, twist and look apply on top of the steadied chest.
